## 二、非功能需求

| ID | 维度 | POC 实现 | 与生产差距 |
|---|---|---|---|
| NFR-001 | 性能 | 未压测；单机 SQLite；模型调用模拟延迟 | 生产需压测 + 容量模型 |
| NFR-002 | 可用性 | 单进程，无 HA | 生产需多副本/主备/维护窗口 |
| NFR-003 | 备份恢复 | 未实现自动备份/演练 | 按院方确认 RTO/RPO 后实施 |
| NFR-004 | 安全 | Token/权限/审计/禁止输出/错误不回堆栈 | 无 TLS/KMS/等保/渗透 |
| NFR-005 | 隐私 | 患者隔离/最小化/授权撤回/审计 | 无 PIA/真实脱敏流水线 |
| NFR-006 | 可观测 | 审计 + 模型调用记录 + 指标 | 无 Prometheus/OTel/告警 |
| NFR-007 | 可维护 | 配置与代码分离；文档脚本 | 无灰度/回滚编排/部署手册 |
| NFR-008 | 兼容 | 现代浏览器；微信小程序 API 契约 | 未做多浏览器/真机矩阵 |
| NFR-009 | 数据隔离 | 患者-用户绑定隔离；应用按科室 | 无机构级多租户 |
| NFR-010 | 审计留存 | 审计表 + 导出权限 | 保留期/WORM 待院方确认 |

## 三、医疗 AI 安全治理（§6）

| 要求 | 实现 |
|---|---|
| 允许/禁止输出 | `safety.scan` 命中诊断/处方/不安全建议→阻断+安全事件+转人工 |
| 风险分级 | 模板 risk_level；高风险事件作为发布阻断项 |
| 人工接管/故障安全 | 模型不可用→拒绝确定性结论+转人工；降级显式标记 |
| 版本与变更控制 | 发布快照固定 8 类版本；回滚恢复配置 |
| 指标口径 | 召回/引用/答案正确/编造率/检出/误报/P95/可用性/闭环时长定义 |

## 四、扩展能力：长期记忆（AgentHub v1.2 重建，非 v1.1 必需）

| 能力 | 实现 | 说明 |
|---|---|---|
| 三级范围 | ✅ | `user`(用户) / `agent`(应用) / `tenant`(default) |
| 四类记忆 | ✅ | preference / fact / summary / instruction |
| 去重 | ✅ | scope+owner+type+content 哈希；重复创建返回 200 并更新重要度 |
| 治理 | ✅ | 软删/停用/启用；硬删仅管理员；过期时间；使用计数 |
| 写入模式 | ✅ | `off` / `session`（结束会话写摘要）/ `auto`（运行后自动写摘要） |
| 向量检索 | ✅ | 64 维 bigram 哈希向量 L2 归一化，余弦 + 关键词加权；`/api/memories/search?mode=vector` |
| 运行/会话记录 | ✅ | `runs` / `sessions`；自动/会话摘要关联 run/session；运营台可查 |
| 试跑注入 | ✅ | 应用配置 `memory_enabled=true` 时检索 Top3，输出标注「结合历史记忆」，写入 `memory` 执行轨迹，累计 use_count |
| 权限 | ✅ | memory:read/write 按角色；患者无临床记忆权限 |
| 患者端隔离 | ✅ | 患者端不使用临床记忆 |

> 该能力来自旧 AgentHub v1.2，属于「中台能力补齐」，不在 v1.1 落地执行包的 FR-001~014 范围内。
